# Requirements review — October 2026

First review in the post-design sequence (requirements → use cases → call
chains → sequences → data model → API). Scope: the requirements docs
after applying the design-round decisions (OQ-55 – OQ-66), checked for
internal consistency and against the approved design (`docs/design/mockups/`).

Each finding has a recommendation and, once made, the stakeholder's decision (recorded as OQ-67 – OQ-78 and applied to the FRs).

## A. Scope the requirements claim that v1 doesn't deliver

**RR-1 — Dashboard customization (FR-6.1, FR-6.7–6.9).** The FRs say users
add, remove, reorder, duplicate and configure Widgets. The approved
Dashboard ships a fixed set, and the earlier mockup work already deferred
customization to v2 — but that deferral was only written in the (deleted)
mockup notes, never in the requirements. The glossary's "Dashboard"
entry repeats the customizable definition.
*Recommend:* mark FR-6.1/6.7–6.9 **deferred to v2**; v1 Dashboard = fixed
widget set as designed. Record as an OQ.
**Decided:** deferred — to **v3** (corrected from v2 during the CUC check, OQ-67); v1 Dashboard is fixed (FR-6.0).

**RR-2 — Notifications (FR-6.5, FR-6.10).** The only remaining trigger
(Open Banking sync failure) is dormant, so a v1 inbox would always be
empty — and the design has no bell in the header.
*Recommend:* defer FR-6.5/6.10 together with Open Banking; keep them as
valid requirements for later.
**Decided:** keep in v1 — invitations are a trigger and more will come (OQ-68). Bell goes in the header.

**RR-3 — Open Banking (FR-2.5, FR-2.6, FR-3.3).** Deferred per the README
and FR-6.5's note, but the FRs themselves don't say so. The design shows
"Import Transactions" disabled.
*Recommend:* tag these FRs explicitly **deferred** (not removed).
**Decided:** deferred to v2 (OQ-69).

**RR-4 — Portfolio Builders (FR-5.5, FR-5.6).** FR-5.5 reads as v1; the
README says CUC-7 is deferred; the design has entry buttons but no flow.
*Recommend:* defer both; remove the two buttons from Investments (or keep
them disabled with "coming later") — decide which.
**Decided:** deferred to v2; buttons stay, disabled (OQ-70).

## B. Requirements with no design yet

**RR-5 — Reporting (FR-6.2, FR-6.3, FR-6.4 CSV export).** Only a
placeholder exists; Transactions has no "Export CSV" action.
*Recommend:* design a Reporting page (spending by category with
drill-down, income vs expense trend, CSV export of filtered transactions)
before development of that area — or defer Reporting to v1.1 and keep
only CSV export (an "Export" button on the filtered ledger). Decide.
**Decided:** all of Reporting incl. CSV export deferred to v2 (OQ-71).

**RR-6 — Audit log export over a date range (FR-7.2).** The nav menu
links straight to a CSV download — no date range, and no Owner/Admin
restriction is visible.
*Recommend:* a small export dialog (date range → download), shown only
to Owner/Admin.
**Decided:** date-range dialog that triggers the download, Owner/Admin only (OQ-77).

**RR-7 — Mixed-currency goal progress (FR-8.4/8.5, FR-9).** A goal
funded by holdings in another currency needs an on-the-fly reference-rate
input on the progress view. No design shows it (all sample goals are
single-currency).
*Recommend:* design the "1 USD = __ BRL" input on the goal progress view
(Goals page card or an expanded goal) — small, but it's the only place FX
exists in the app.
**Decided:** add the exchange-rate input to the goal view — design for review on Superdesign.

**RR-8 — Archive a Holding (FR-5.8).** Holdings rows are read-only in the
design; there is no archive action.
*Recommend:* add "Archive" to the expanded holding row (only when its
quantity is zero, e.g. after a full sell/redemption) — or confirm archive
happens automatically at zero quantity. Decide.
**Decided:** auto-archive at zero quantity via the transaction; notification suggesting archive when a fixed-term Holding is past due (OQ-72).

**RR-9 — Create another household (FR-1.4 + FR-1.8).** The switcher
lists households and invitations but no "Create household".
*Recommend:* add "Create household" to the switcher menu (runs the
name-your-household step; guided setup applies as for the first one?).
**Decided:** add "Create household" to the switcher — design for review on Superdesign (OQ-75).

## C. Mismatches between design and requirements

**RR-10 — Account types (FR-2.1, FR-3.8).** FRs allow checking, savings,
credit card, cash, investment, other — and investment transactions must
target an **investment-type** account. The design's add-account forms
show only Checking / Savings / Credit card only, and old sample data put
stocks under "Main Checking".
*Recommend:* account type picker shows all six types; holdings only ever
live under investment accounts (fix sample data when building).
**Decided (different from recommendation):** 4 types — checking, savings, credit card only, investment; investments can live in any account except credit card only (OQ-76).

**RR-11 — Fixed-term instrument list (FR-11.1).** FR-11.1 lists CDB, LCI,
LCA, Tesouro Direto, CDs, Treasury bonds. The investment-buy design also
offers CRA, CRI, Debenture, LC, LF (fixed income) and Currency, Crypto,
Real estate, Mutual fund. FR-5.1's asset-type list is shorter still.
*Recommend:* align FR-5.1 and FR-11.1 to the designed lists (they're
reference data, so this is a data change, not a schema one) — and confirm
the engine's v1 tax rules cover every fixed-income type offered.
**Decided:** v1 fixed-term list as recommended (incl. debenture "incentivised" flag, Treasury by currency); US expected taxes "not estimated"; FR-5.1 gets the full market-priced list (OQ-79).

**RR-12 — Monthly payout / yield (Investments overview).** The design
shows "monthly yield" and "R$/mo" per stock/FII. No FR defines how that's
computed.
*Recommend:* define it as **trailing-12-month dividends ÷ 12** (and yield
= that ÷ current value), derived from dividend transactions — or drop the
cards. Decide.
**Decided:** payout derived from dividend/interest transactions linked to the Holding; current-month payout + new payout-over-time chart with Holding selector on Investments overview and Dashboard (FR-5.9, OQ-73).

**RR-13 — Monthly In / Out / Total and the month strip (Transactions).**
The design's period summary (In, Out, Total per currency) and the
12-month mini in/out bars aren't in any FR (FR-6.3's income-vs-expense
trend is close but is a report).
*Recommend:* add an FR: per currency, monthly inflow, outflow and net,
excluding transfers between own accounts (FR-3.6) and credit card bill
payments (FR-3.11).
**Decided:** added as FR-6.11 (OQ-74).

**RR-14 — "Archive" vs "Completed" for goals (FR-8.8/8.9).** The UI says
"Mark completed" / "Completed" list; the FRs say archive/unarchive.
*Recommend:* rename in the FRs to complete/reopen — clearer, and it's the
only reversible "archive" in the system, which was confusing anyway.
**Decided:** complete / reopen (OQ-78).
