UC-18: Reset Forgotten Password

Use case 18 of 21 in the Identity & Household set (docs/requirements/01-core-use-cases.md, CUC-2). Traces to FR-1.13. Unauthenticated flow — must work precisely when the user can't log in. High-level activity view only — no component names or API details yet. Two backend round-trips.

Password minimum 12 characters (NFR-SEC-4, OQ-64).

Response is the same whether or not the email exists: a security-hygiene default — the confirmation step must not let an attacker distinguish "no such account" from "reset sent," so the backend's first response is generic regardless of lookup outcome.

Invalidates all sessions: if someone reset the password, any prior session (possibly the attacker's, if the account was compromised) should not survive it.
