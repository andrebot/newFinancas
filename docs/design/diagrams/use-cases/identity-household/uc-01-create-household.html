Two entry points (FR-1.4, OQ-75, Oct 2026 review): onboarding, or 'Create household' in the main menu's household switcher. Either way the guided setup follows, with the first account mandatory (FR-1.22, OQ-81).

Reading this diagram: deliberately non-technical — no URLs, no manager/accessor names, no auth-middleware placement. Those are component-call decisions that come later, once the full 19-use-case set for this area is confirmed.

Outcome (FR-1.4/FR-1.6): the creating user is automatically assigned the Owner role on the new household — not a separate step the user performs.

Default categories (FR-10.1), fixed after a gap was found: creating a household also seeds the predefined default Category set — the user never has to set this up manually before categorizing their first transaction. On the backend this is a Manager↔Manager effect routed through pub/sub, not a direct call — see docs/architecture/backend/01-vbd-decomposition.md §3.1b.

Precondition: user is already authenticated (see UC for Login).
