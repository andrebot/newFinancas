Account Setup — Goal Management

POST/PATCH/DELETE /households/:householdId/goals, POST /households/:householdId/goals/:id/complete|reopen, GET /households/:householdId/goals (definitions, AccountManager) + GET /households/:householdId/goal-progress (progress, InsightsManager — OQ-177).

sequenceDiagram
    actor User
    participant GF as Goal Form
    participant GP as Goal Progress Card
    participant FX as Exchange-Rate
Calculator
    participant CR as Complete / Reopen
Confirm
    participant FLOW as Goal Management
Flow
    participant EXP as Account Setup
Experience
    participant API as Backend API
    FLOW->>EXP: request goals(status)
    par definitions
        EXP->>API: GET /households/:householdId/goals?status=active
        API-->>EXP: goals (name, target, due date, visibility)
    and progress
        EXP->>API: GET /households/:householdId/goal-progress?status=active
        API-->>EXP: per-currency contributions + funded by, per goal
    end
    EXP-->>FLOW: state (progress joined by goal id)
    FLOW-->>GP: render progress
    opt goal mixes currencies
        User->>FX: '1 USD = 5.20 BRL'
        FX->>FLOW: emit rateEntered (kept in Flow state only)
        FLOW-->>GP: re-render blended estimate (nothing sent)
    end
    alt create / edit
        User->>GF: name, currency, visibility, target, due date
        GF->>FLOW: emit goalSubmitted
        FLOW->>EXP: request saveGoal
        EXP->>API: POST /households/:householdId/goals (or PATCH)
    else complete / reopen
        User->>CR: confirm
        CR->>FLOW: emit transition
        FLOW->>EXP: request complete or reopen
        EXP->>API: POST /households/:householdId/goals/:goalId/complete (or /reopen)
    end
  • Allocations are never edited here — always from the Holding (OQ-48).
  • FX never leaves the browser (FR-9).
  • Definitions and progress are two reads (OQ-177): the Goal list is AccountManager's own; progress, a reshaped read, is InsightsManager's. A completed Goal can still be edited.
