Onboard — Registration

POST /auth/register. Skipped by configuration when already signed in (OQ-81). One form, one request (OQ-148).

sequenceDiagram
    actor User
    participant RF as Registration Form Entry
    participant FLOW as Registration
Flow
    participant EXP as Onboard
Experience
    participant API as Backend API
    User->>RF: first + last name, email, password + confirm (strength meter, advisory)
    RF->>FLOW: emit submit(registration) — names not blank, valid email, ≥ 12 characters, confirmation matches
    FLOW->>EXP: request register(registration)
    EXP->>API: POST /auth/register
    alt 409 user.email_taken / 422 password.too_short (or another failure)
        API-->>EXP: error code
        EXP-->>FLOW: outcome: failed(code)
        FLOW-->>RF: email_taken under the email, too_short under the password, anything else in the banner — typing kept
    else 201 created
        API-->>EXP: userId + TOTP secret + recovery codes (kept by the Experience)
        EXP-->>FLOW: outcome: ok (Flow stays busy)
        EXP->>EXP: advance to MFA Enrollment
    end
    User->>RF: Sign in instead
    RF->>FLOW: emit signIn
    FLOW->>EXP: emit signIn → Sign In
  • First/last name split (OQ-29); names and email are trimmed before sending.
  • No terms box: mockup 02's "I agree to the Terms" is dropped for v1 (OQ-148).
  • The TOTP secret and recovery codes never pass through this Flow; the Experience hands them to MFA Enrollment.
  • The strength meter rates the password against the name and email typed.
