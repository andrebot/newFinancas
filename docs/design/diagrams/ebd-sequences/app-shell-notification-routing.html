App Shell — Notification Routing

GET /notifications, POST /notifications/seen, DELETE /notifications/:id + the owning Experience's own endpoint.

    participant TI as Track Investments
Experience
    participant API as Backend API
    SHELL->>API: GET /notifications (via Review Insights) — read-only, every 60s while the tab is in front, and on focus
    API-->>SHELL: [{id, type, params, seenAt}]
    SHELL-->>BELL: badge = count of seenAt null
    User->>BELL: open the bell
    BELL->>API: GET /users/me/invitations — names an invitation notice (one no longer there: "no longer open", delete only)
    BELL-->>User: render each via I18nUtility (type → catalog string, IDs resolved)
    BELL->>API: POST /notifications/seen {ids unseen when it opened, ≤200 a call} (OQ-105) — they stay "new" while open
    alt invitation.received — Accept
        User->>BELL: Accept
        BELL->>SHELL: emit action {type: invitation.received, accept, params}
        SHELL->>MP: route (routing config) → Respond to Invitation (OQ-159)
        MP->>API: POST /invitations/:invitationId/accept
        MP-->>SHELL: done / failed (Manage Profile toasts either)
    else holding.matured — Archive holding
        User->>BELL: Archive holding
        BELL->>SHELL: emit action {type: holding.matured, archive, params}
        SHELL->>TI: route → Archive Matured Holding
        TI->>API: POST /households/:householdId/holdings/:holdingId/archive — the notice's householdId, else the active one (OQ-245)
        TI-->>SHELL: done / failed (Track Investments toasts either — the Holdings, overview and Goals refetch by tag, a Holding gone is done)
    end
    opt done
        SHELL->>BELL: dismiss (Review Insights' own)
        BELL->>API: DELETE /notifications/:notificationId
    end
    opt holding.matured — View holding (OQ-243)
        User->>BELL: View holding
        BELL-->>User: close, switch to the notice's household if it names another the user still belongs to (else a toast, OQ-245), then navigate to /investments?tab=holdings&holding=:holdingId — its account chosen, its row open
    end
    opt the row's ✕
        User->>BELL: delete
        BELL->>API: DELETE /notifications/:notificationId (Review Insights' own)
    end
  • The inbox never performs the action itself — the owning Experience does (Q3). An action no Experience owns comes back `unrouted`: the inbox says so in a toast.
  • A new type = one routing entry + one catalog string.
  • The bell is the user's, not a household's: a matured notice names its Holding's household, which Archive holding archives in and View holding switches to (OQ-245).
