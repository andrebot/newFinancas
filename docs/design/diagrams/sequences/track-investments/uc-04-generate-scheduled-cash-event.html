Generate Scheduled Investment Cash Event

System-triggered by investmentsDaily, no HTTP route — FR-11.3. Re-enters the exact Record Transaction pipeline (VBD §3.2a).

sequenceDiagram
    participant CRON as investmentsDaily
    participant IHA as InvestmentHoldingAccessor
    participant SB as ServiceBusUtility
    participant TM as TransactionManager
    participant ATA as AccountTransactionAccessor
    participant LOG as LoggingUtility

    CRON->>IHA: findDueScheduleEntries(today)
    Note over IHA: reads the schedule (and coded taxes) InvestmentProductEngine
computed at buy time — the Engine is NOT called again
    IHA-->>CRON: [{entryId, holdingId, accountId, kind, amount, date}, ...]
    loop for each due entry
        CRON->>SB: publish("transaction.import.requested", {entryId, ...})
        SB-->>TM: subscribe("transaction.import.requested")
        TM->>IHA: markEntryPosted(entryId)
        alt already posted (a repeated delivery)
            IHA-->>TM: false
            Note over TM: nothing more — the entry posted once (OQ-171)
        else marked now
            IHA-->>TM: true
            Note over TM: same recordTransaction(...) pipeline as POST /households/:householdId/transactions,
in the same database transaction — kind = interest / redemption / tax,
linked to the Holding, a redemption that zeroes it auto-archives it (OQ-72)
            TM->>ATA: insert({…transaction, effect, holdingId, source: schedule})
            ATA-->>TM: transaction
        end
        TM-->>LOG: logActivity(correlationId, systemActor, "PostScheduledCashEvent")
        TM-->>LOG: recordAudit(systemActor, "Transaction", transactionId)
    end
  • Posted once (OQ-171): markEntryPosted runs in the same database transaction as the posted Transaction and only marks an unposted entry, so a repeated event delivery posts nothing twice.
  • Payout source (FR-5.9): the interest transactions posted here, linked to their Holding, are what the payout chart reads.
  • OQ-201: index-linked amounts are the projections made at buy time — the user edits a posted one to what the bank paid, or deletes it (it isn't posted again). At maturity interest (gross), tax and redemption (principal) post as three entries on the same date, each moving the account's cash.
  • The same investmentsDaily run also publishes holding.matured (UC-11) — one cron, two events (Manager review M6).
  • See FR-11.2, FR-11.3, FR-5.9, OQ-72.
