  • Two Engines side by side, never calling each other — InsightsManager composes them (VBD §3).
  • Payout comes only from linked transactions (FR-5.9); projections are computed on read (FR-11.2) — nothing new is stored.
  • The Rates tab reads GET /households/:householdId/index-rates (every index with its history) — a plain read of AccountManager's own entities, so it is AccountManager's (IndexRateAccessor.list, read-ownership rule, OQ-172), not this Manager's; so are a Holding's value history (GET …/holdings/:holdingId/valuation-snapshots), its schedule (…/schedule-entries) and its visible Goal split (…/allocations) — built in M2 part 5 (OQ-178).
  • As built in M4 (OQ-208): GET …/accounts/:accountId/holdings and GET …/holdings/:holdingId read the rows straight from InvestmentHoldingAccessor — there is no ReportingEngine positions use case — and project each fixed-term one on read: its buy's date and amount come from AccountTransactionAccessor.findBuys (one read for the whole list), then only InsightsManager calls InvestmentProductEngine.project (OQ-178, OQ-205). A Holding takes its Account's access; an unseen one answers the entity's own not-found.
  • As built in task 133 (OQ-236): net worth is the visible Holdings' value only (FR-5.4) — a month's figure on its last day, archived Holdings included for the months they held value; the series starts at the first month with value, and the change is left out when it holds only this month. Coming Due carries each contract's principal, as net worth counts it. A payout is a dividend or interest transaction linked to its Holding (AccountTransactionAccessor.listPayouts).
