Recover MFA via Backup Code

POST /auth/mfa/recover — FR-1.16/OQ-145. Login's second step with a single-use recovery code in place of the MFA code; exhausting/losing all of them falls outside self-service (OQ-24), not modeled here.

    Note over User,LOG: after Login's password step answered {challengeToken} (UC-14)
    User->>API: POST /auth/mfa/recover {challengeToken, recoveryCode}
    API->>IM: recoverWithCode(input, deviceInfo = User-Agent)
    IM->>AN: verifyChallengeToken(challengeToken)

    alt challenge expired or not valid
        IM-->>API: Unauthorized
        API-->>User: 401 auth.challenge_expired (start again)
    else challenge valid
        IM->>UA: findLoginLock(emailKey), then findByEmail(email)
        UA-->>IM: lockedUntil, user
        Note over IM: locked → 429 — user gone or not the one challenged → challenge_expired
        IM->>AN: hashRecoveryCode(recoveryCode)
        AN-->>IM: codeHash
        IM->>UA: consumeRecoveryCode(userId, codeHash, now)
        Note over UA: atomic UPDATE … WHERE unused — single-use (FR-1.16),
never reached without a proven password, so no code is wasted
        UA-->>IM: consumed / not
        alt code used or unknown
            IM->>UA: recordLoginFailure(emailKey, …) (+ lockLogin at 5)
            IM-->>API: Unauthorized
            API-->>User: 401 auth.mfa_invalid (retry the code)
        else code consumed
            IM->>UA: clearLoginFailures(emailKey)
            IM->>AN: issueOpaqueToken()
            AN-->>IM: {token, tokenHash}
            IM->>SA: insert(userId, tokenHash, deviceInfo, expiresAt, now)
            SA-->>IM: session
            IM->>AN: signAccessToken({userId, sessionId, systemRole})
            AN-->>IM: accessToken
            IM-->>LOG: log.audit("MfaRecovery", Session sessionId)
            IM-->>API: {accessToken, refreshToken}
            API-->>User: 200 OK {accessToken, refreshToken}
        end
    end
  • Functionally an alternate second factor to Login's TOTP step, not a separate account-recovery mechanism — it needs the challenge from Login's password step, so the password is always proven first.
  • Same second step as Login (OQ-145): the same challenge check, the same lockout (a wrong code counts like a wrong password, OQ-114) and the same auth.mfa_invalid for a used or unknown code — naming the code is safe once the password is proven.
  • v1 scope limit (FR-1.16): if recovery codes are also exhausted or lost, there is no further self-service path — a manual/support-assisted process outside this system, not diagrammed since it isn't a backend flow (OQ-24).
  • See FR-1.16, OQ-24, OQ-114, OQ-145.
