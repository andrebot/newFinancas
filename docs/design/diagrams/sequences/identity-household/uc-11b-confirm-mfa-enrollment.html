Confirm MFA Enrollment

POST /auth/mfa/enrollment/confirm — FR-1.15/OQ-149. The first authenticator code proves the app was set up: it confirms the enrollment, once, and opens the first session. Follows Create User (UC-11), or a sign-in to an unconfirmed account (UC-14).

  • Why a confirmation step (OQ-149): registration answers the secret once; without a live code nothing proves the user's app holds it, and a wrong scan would only show at the next sign-in — with no way back in. The first code closes that gap and is also what signs the new user in, so Onboard continues to Household Setup with a session.
  • Same protections as sign-in's second step: the enrollment token is a stateless JWT with its own audience (it never passes as a challenge or an access token), wrong codes count against the per-address lockout (OQ-114), and success clears it.
  • An unconfirmed account can always finish: the token lasts 15 minutes (config/constants.ts); after that, signing in with the password answers a fresh enrollment (UC-14), replacing the secret and recovery codes no one saw.
