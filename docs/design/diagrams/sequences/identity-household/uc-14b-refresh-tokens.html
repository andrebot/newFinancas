Refresh Tokens

POST /auth/refresh — OQ-30/OQ-100/OQ-106. Exchanges a refresh token for a new pair; each refresh token works once. Part of staying signed in after Login (UC-14).

sequenceDiagram
    actor User
    participant API as Hono route
    participant IM as IdentityManager
    participant AN as AuthenticationUtility
    participant SA as SessionAccessor
    participant UA as UserAccessor
    participant LOG as LoggingUtility

    User->>API: POST /auth/refresh {refreshToken}
    API->>IM: refresh(refreshToken)
    IM->>AN: hashOpaqueToken(refreshToken)
    AN-->>IM: presentedHash
    IM->>AN: issueOpaqueToken()
    AN-->>IM: {token, tokenHash}
    IM->>SA: rotate(presentedHash, tokenHash, expiresAt = now + 30 days, now)
    Note over SA: guarded: applies only while presentedHash is the session's
current, unexpired token, and remembers it as the previous one
    alt rotated
        SA-->>IM: session
        IM->>UA: findById(session.userId)
        UA-->>IM: user (systemRole)
        IM->>AN: signAccessToken({userId, sessionId, systemRole})
        AN-->>IM: accessToken
        IM-->>API: {accessToken, refreshToken = token}
        API-->>User: 200 OK
    else stale
        SA-->>IM: stale
        IM->>SA: findByReplacedToken(presentedHash)
        alt it was already used — a replay, likely a stolen token
            SA-->>IM: {sessionId, userId}
            IM->>SA: deleteForUser(userId, sessionId)
            Note over IM: ends that session only — the user's other devices stay signed in
            SA-->>IM: deleted
            IM-->>LOG: log.warn("Refresh token replayed — session ended")
        else unknown, expired or revoked
            SA-->>IM: none
        end
        IM-->>API: Unauthorized
        API-->>User: 401 auth.refresh_invalid
    end
  • Rotation: every refresh issues a new refresh token (30-day sliding expiry) and consumes the old one, so each works once (OQ-100).
  • Replay ends that session only (stakeholder decision, Oct 2026): whoever holds the old token — thief or victim — must sign in again on that device; other devices are untouched, and an attacker replaying an old token can't sign the user out everywhere.
  • The system role comes from the user record at each refresh, so a role change takes effect within one access-token lifetime (OQ-111).
  • No access token needed — this is how a client gets one back after it expires.
