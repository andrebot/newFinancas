Invite User to Household

POST /households/:householdId/invitations — FR-1.5/FR-1.19/OQ-26. Owner/Admin only; target must be an existing registered user — there is no invite-a-non-user flow.

    User->>API: POST /households/:householdId/invitations {email, role}
    API->>IM: inviteUser(actor, householdId, {email, role})
    IM->>AZ: authorize(actor.userId, householdId, members.manage)
    alt not a member
        AZ-->>IM: not_member
        IM-->>API: NotFound
        API-->>User: 404 household.not_found
    else not Owner or Admin
        AZ-->>IM: forbidden
        IM-->>API: Forbidden
        API-->>User: 403 auth.forbidden
    else allowed
        AZ-->>IM: allowed
        IM->>UA: findByEmail(email, trimmed)
        alt no registered user (FR-1.19, the Manager's rule, OQ-109)
            UA-->>IM: none
            IM-->>API: NotFound
            API-->>User: 404 invitation.invitee_not_registered
        else registered
            UA-->>IM: invitee
            IM->>HA: findMembership(householdId, invitee)
            IM->>IA: findPending(householdId, invitee)
            alt already a member
                IM-->>API: Conflict
                API-->>User: 409 invitation.already_member
            else already invited
                IM-->>API: Conflict
                API-->>User: 409 invitation.already_pending
            else neither
                IM->>IA: insert({householdId, invitedUserId, invitedByUserId: actor, role})
                Note over IA: one pending invitation per person per household — a
simultaneous second invite fails the unique index (OQ-118)
                alt lost a race
                    IA-->>IM: already_pending / invitee_missing
                    IM-->>API: Conflict / NotFound
                    API-->>User: 409 invitation.already_pending / 404 invitee_not_registered
                else inserted
                    IA-->>IM: invitation (pending)
                    IM-->>NE: notify("invitation.received", {userId: invitee}, {invitationId, householdId, inviterUserId, role})
                    Note over NE: routed in-app (OQ-113) — fire-and-forget,
a failure is logged and the invitation stands
                    NE->>NIA: insert(invitee, "invitation.received", params)
                    IM-->>LOG: log.audit("InviteUser", Invitation invitationId, household)
                    IM-->>API: invitation
                    API-->>User: 201 Created Invitation
                end
            end
        end
    end
  • FR-1.19's "existing user only" rule is the Manager's (OQ-109): it looks the email up and answers 404 invitation.invitee_not_registered. The invited_user_id NOT NULL foreign key is the backstop for an account deleted in between (invitee_missing), and a partial unique index allows one pending invitation per person per household, so two simultaneous invites can't both land (OQ-118).
  • The notification is fire-and-forget — the 201 response doesn't wait on it. NotificationEngine chooses the channel (in-app for invitation.received, OQ-68); the Manager only says what happened and to whom (OQ-113).
