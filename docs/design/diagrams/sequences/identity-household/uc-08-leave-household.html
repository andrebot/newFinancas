Leave Household

DELETE /households/:householdId/members/:userId (userId = the caller) — FR-1.11/FR-1.18. Self-service, no authorization check. If the leaving member is the Owner, the longest-tenured member takes over first, or the household dissolves when nobody else is left.

sequenceDiagram
    actor User
    participant API as Hono route
    participant IM as IdentityManager
    participant HA as HouseholdAccessor
    participant LOG as LoggingUtility

    User->>API: DELETE /households/:householdId/members/:userId (userId = the caller)
    API->>IM: removeMember(actor, householdId, actor.userId)
    Note over IM: self-service — no permission check. Each attempt decides from
fresh facts, a stale guarded write starts it again, 3 attempts at most (OQ-107)
    loop up to 3 attempts
        IM->>HA: findMembership(householdId, actor.userId)
        alt not a member
            HA-->>IM: none
            IM-->>API: NotFound
            API-->>User: 404 household.not_found
        else a member who is not the Owner
            HA-->>IM: Admin / Member / Viewer
            IM->>HA: removeMember(householdId, actor.userId)
            HA-->>IM: removed (stale → next attempt)
        else the Owner
            HA-->>IM: Owner
            IM->>HA: findSuccessor(householdId, actor.userId)
            alt nobody else is a member
                HA-->>IM: none
                IM->>HA: dissolve(householdId, actor.userId)
                Note over HA: guarded — only while nobody else is a member, so someone
who just accepted an invitation isn't deleted with it (OQ-117)
                HA-->>IM: dissolved (stale → next attempt)
            else a successor (longest-tenured Admin, then Member, then Viewer)
                HA-->>IM: successor
                IM->>HA: swapOwner(householdId, actor.userId, successor)
                HA-->>IM: swapped (stale → next attempt)
                IM->>HA: removeMember(householdId, actor.userId)
                HA-->>IM: removed (now an Admin)
            end
        end
    end
    alt still stale after 3 attempts
        IM-->>API: Conflict
        API-->>User: 409 household.changed
    else left or dissolved
        IM-->>LOG: log.audit("LeaveHousehold" or "DissolveHousehold", Household householdId)
        IM-->>API: left
        API-->>User: 204 No Content
    end
  • All branches return the same 204, but the decisions are IdentityManager's (OQ-107): who succeeds, and whether the household dissolves. HouseholdAccessor applies each step as a guarded write and says stale when the facts changed meanwhile — the whole decision then runs again from fresh facts, up to three times (households.leaveAttempts), before a 409. dissolve is guarded too (OQ-117): someone who joined a moment ago is never deleted with the household.
  • This is the richest of the three "membership ends" flows (Remove Member, Leave, and — via FR-1.17 — Delete User) precisely because it's the one place FR-1.18's succession rule is directly, voluntarily triggered rather than a side effect of account deletion.
  • See FR-1.11, FR-1.18, OQ-25, OQ-27.
