Revoke Household Invitation

DELETE /households/:householdId/invitations/:invitationId — FR-1.10. Owner/Admin cancels a still-pending invitation before the invitee responds.

sequenceDiagram
    actor User
    participant API as Hono route
    participant IM as IdentityManager
    participant AZ as AuthorizationUtility
    participant IA as InvitationAccessor
    participant LOG as LoggingUtility

    User->>API: DELETE /households/:householdId/invitations/:invitationId
    API->>IM: revokeInvitation(actor, householdId, invitationId)
    IM->>AZ: authorize(actor.userId, householdId, members.manage)
    alt not a member
        AZ-->>IM: not_member
        IM-->>API: NotFound
        API-->>User: 404 household.not_found
    else not Owner or Admin
        AZ-->>IM: forbidden
        IM-->>API: Forbidden
        API-->>User: 403 auth.forbidden
    else allowed
        AZ-->>IM: allowed
        IM->>IA: findById(invitationId)
        alt missing, or another household's
            IA-->>IM: none / elsewhere
            IM-->>API: NotFound
            API-->>User: 404 invitation.not_found
        else this household's
            IA-->>IM: invitation
            IM->>IA: resolve(invitationId, revoked, now)
            alt no longer pending (answered meanwhile)
                IA-->>IM: stale
                IM-->>API: Conflict
                API-->>User: 409 invitation.not_pending
            else resolved
                IA-->>IM: resolved
                IM-->>LOG: log.audit("RevokeInvitation", Invitation invitationId, household)
                IM-->>API: revoked
                API-->>User: 204 No Content
            end
        end
    end
  • Distinct actor/authorization path from Decline (FR-1.11's framing applied to invitations, not membership) — the invitee ends it by declining, the inviter/Admin ends it by revoking, same underlying status transition either way.
  • See FR-1.5, FR-1.10.
