Create Financial Account

POST /households/:householdId/accounts — FR-2.1/2.7. type and currency are immutable once set (OQ-32) — there is no edit path for either, ever. The Account and its cards are written together or not at all (OQ-175).

    actor User
    participant API as Hono route
    participant AM as AccountManager
    participant AU as AuthorizationUtility
    participant VU as ValidationUtility
    participant UW as UnitOfWorkUtility
    participant AA as AccountAccessor

    User->>API: POST /households/:householdId/accounts {name, type, currency, visibility, openingBalance?, cards?: [{network, last4, closingDay, dueDay, expirationMonth, expirationYear}]}
    Note over API: contract check first: type, currency, CardNetwork,
last4 = 4 digits, days 1–31, month 1–12 → 422 validation.failed
    API->>AM: createAccount(context, householdId, input)
    AM->>AU: authorize(actor, householdId, {data.create, visibility, ownerUserId: actor})
    alt not a member
        AU-->>AM: not_member
        AM-->>API: 404 household.not_found
    else shared Account by a role that may not create (Viewer)
        AU-->>AM: forbidden
        AM-->>API: 403 auth.forbidden
    else allowed (a personal Account is anyone's own)
        AU-->>AM: allowed
        AM->>VU: checkFields({name: nonBlank})
        alt blank name
            AM-->>API: 422 validation.failed {name}
        else cards on an investment Account (FR-2.7)
            AM-->>API: 422 account.cards_not_allowed
        else valid
            AM->>UW: inTransaction(work)
            Note over UW,CA: one DB transaction — the work gets both Accessors over it
            AM->>AA: insert({householdId, ownerUserId: actor, name, type, currency, visibility, startingBalance, startingBalanceDate: today})
            Note over AA: also writes the first account_month_balances row,
opening and ending at the opening balance (OQ-169)
            loop each card, one at a time
                AM->>CA: insert({accountId, ...card}, today)
                Note over CA: first credit_card_month_balances row at 0,
in the billing cycle today falls in (OQ-170)
            end
            UW-->>AM: committed (a failure rolls every write back)
            AM-->>LOG: audit CreateAccount, AttachCreditCard per card
            AM-->>API: Account {currentBalance: openingBalance, cards: outstandingBalance 0}
            API-->>User: 201 Created
        end
    end
  • Attaching a card at creation is optional (FR-2.7 doesn't require an account to have a card at all) — the same combined-form principle used for editing (OQ-35) applies from the start.
  • “Today” is the app time zone's date (OQ-104), read from the Manager's clock.
  • Oct 2026 review: four account types (OQ-76); also the mandatory first step of every household's guided setup (FR-1.22).
