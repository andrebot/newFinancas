Create Budget

POST /households/:householdId/budgets — FR-4.1/4.7. A Category or Subcategory can be claimed by at most one Budget per scope — a real partial-unique-index constraint, not application logic. The Budget, its claims and this month's period are written together or not at all (OQ-166).

  • The literal-duplicate rejection (FR-4.7) is a real DB constraint one layer down — partial unique indexes on budget_targets, per scope (shared: per household; personal: per household + owner, OQ-95), scoped columns denormalized specifically to make this a plain index rather than a cross-table application check.
  • The rollup half (a claimed Category reserves its Subcategories, both ways) is checked by the Accessor before each insert, under the parent Category's row lock (OQ-166).
  • Each scope claims a Category once: the same Category can sit in one shared Budget and in each member's personal Budget; a spend counts toward the Budget of its Account's scope (OQ-166). So the claiming Budget named by a 409 is always one the caller can see.
  • The generated validator can't say “exactly one of categoryId / subcategoryId”, so the Manager checks it; a target sent twice is claimed once (OQ-176).
  • “This month” is the app time zone's (OQ-104), from the Manager's clock.
  • Corrected (PR #145): a spend counts as it is written, so a Budget created mid-month used to miss the month's earlier spends. The Manager now restates its spend from this month on, from the transactions already in its scope — the Accounts and their cards a spend of it accrues from, matched on the same claims and signed the same way (managers/budgetSpend.ts).
