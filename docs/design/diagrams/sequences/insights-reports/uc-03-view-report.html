View Report

Ad-hoc report types deferred to v2 (OQ-71) — the /reports/:reportType resource itself is v1, serving the fixed types month-overview, investments-overview, payouts. GET /households/:householdId/reports/:reportType?year=&month= — FR-6.2/6.3/6.6, FR-6.11. As built in M4 (OQ-208): month-overview is served; the other two answer 400 until task 133.

  • As built in M4 (OQ-208): the route is the contract's parameterized operation from day one; a v1 type this build does not serve yet answers 400 report.unknown_type_or_range, the code the contract reserves for this endpoint. The Manager only decides which month was asked for (each part defaults to today's, OQ-104) and hands the viewer to ReportingEngine — all narrowing is the Engine's (OQ-206). Every member role may read it: data.view is everyone's on shared data (OQ-111), so a Viewer sees the same report, narrowed to what they can see.
  • Lands with task 133: investments-overview and payouts, beside their first caller — the same generic use case, different parameters (spend-by-category, income-vs-expense, account-balance-by-month stay deferred to v2, OQ-71).
  • FR-6.6 states this explicitly for account-balance-by-month, and it holds for the other two: "this requires no new stored data... a reporting view over existing history, not a new data-model concept."
