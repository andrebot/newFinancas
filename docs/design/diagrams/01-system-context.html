System Context Diagram — New Finance App

C4 Level 1 (Context). Reflects the core use cases in docs/requirements/01-core-use-cases.md. Dashed elements are future-phase.

Person

Household Member

Owner, Admin, Member, or Viewer of a household. Manages accounts, transactions, budgets, and investments.

Software System

New Finance App

Household budgeting, expense tracking, and investment/net-worth tracking. Manual entry first, Open Banking optional.

External System — 2 regions

Open Banking / Open Finance Providers

Supplies account balances and transactions for linked accounts (FR-2.5, FR-3.3). Confirmed multi-region: Open Finance Brasil (BRL) + a US-oriented provider (USD), one interface.

External System — Future Phase

Market / Analysis API

FII & stock recommendations and graph-based analysis (FR-5.7). Explicitly out of scope for v1.

External System — volatile

Notification Channel

Delivers budget/sync alerts (FR-6.5). In-app is the confirmed v1 minimum; channel is abstracted since more (email, push, SMS) are expected later.

Reading this diagram: this is intentionally a context-level view only — no internal components yet. The internal decomposition (Managers/Engines/Resource Accessors on the backend, Experiences/Flows/Interactions on the frontend) is the subject of the next design step, informed directly by the volatility notes in docs/requirements/01-core-use-cases.md: the Open Banking Providers, the Notification Channel, and the future Market/Analysis API are all flagged [volatile] there, which is why all three are drawn as isolated external systems rather than assumed to be part of the core system.
